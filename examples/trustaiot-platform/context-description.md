# Context Description — TrustAIoT Worked Example

This document is an **illustrative retrospective completion** of the
`context-description.md` template using documentary evidence from the
TrustAIoT case.

It is not an original TrustAIoT project record and does not imply prospective
application of CRISP-TAI.

This worked artefact primarily illustrates **CR.4 — Assumption
Documentation** and contextual information supporting the retrospective
reconstruction described in `/logs/trustaiot-retrospective-application.md`.

## 10. Revision conditions

| Revision condition | Affected contextual element | Evidence source | Responsible role |
|---|---|---|---|
| Material regulatory or policy change | Governance assumptions or constraints | Regulatory / policy evidence | Relevant governance actor |
| Material change in platform or operating conditions | Operational assumptions | Platform or operational evidence | Relevant platform actor |
| Monitoring or validation evidence challenging an existing assumption | Contextual interpretation or assumption | Monitoring / validation evidence | Relevant governance and operational actors |
| User feedback indicating changed expectations or problems | Contextual interpretation | User-feedback mechanisms | Relevant governance / platform actor |
| Maintenance or update event affecting existing controls | Continuity assumptions | Change-management / maintenance evidence | Relevant lifecycle owner |

Where such evidence challenges an existing contextual interpretation, the
retrospective refinement path corresponds to **CR.5 — Context Revision
Trigger**.
